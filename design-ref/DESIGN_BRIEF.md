# Amber 音乐播放器 — 设计需求文档（Design Brief）

> 交付对象：负责 UI 设计与实现的 Claude / 设计师
> 版本：v1 · 2026-08-14
> 一句话目标：**做一个符合 Apple 设计规范、体验丝滑的 macOS 原生音乐软件**——功能对齐 Apple Music / 现有 Amber，视觉与交互不追求 1:1 复刻，追求"用起来舒服"。

---

## 0. 这份文档怎么用

- **功能是硬约束**：第 5 章的功能清单必须全部覆盖，因为背后的 provider（QQ / 网易云）能力已经做好了。
- **视觉与交互是自由区**：第 3~4、6~8 章给的是**原则和约束**，不是像素稿。你有权重新设计布局、配色、动效，只要落在 Apple Human Interface Guidelines（macOS）之内、且服务于"丝滑"这个核心目标。
- 冲突时的优先级：**Apple 原生体验 > 丝滑流畅 > 功能完整 > 视觉美观 > 与 Apple Music 相似**。
- 明确的**非目标**：不做 Apple Music 的像素级复刻，不追求和它长得一样。

---

## 1. 背景与设计哲学

现有 Amber 是一个纯 Swift 原生栈（SwiftUI + AppKit + AVFoundation）的 macOS 音乐播放器，聚合 QQ 音乐与网易云两个音源，零第三方依赖。此前的方向是"像素级复刻 Apple Music"，现在**放弃复刻**，转向自主设计。

**为什么转向**：长得像不等于好用。真正想要的是 Apple 生态里那种"顺滑、克制、不打扰"的体验感。

**五条设计信条**：

1. **原生优先（Native First）**：能用系统组件、系统材质、系统语义色就用，不自己造轮子。窗口、工具栏、侧栏、右键菜单都走 macOS 标准行为。
2. **液态玻璃（Liquid Glass）**：全面拥抱 macOS 26 的 Liquid Glass 设计语言。Chrome 层（侧栏、工具栏、播放条、控件、popover）用系统 Liquid Glass 材质，让界面框架"漂浮"在内容之上、随内容折射流动。这是本次视觉的主基调（见第 7.2 节）。
3. **内容优先（Content First）**：专辑封面和音乐内容是主角，玻璃 Chrome 要透、要让位。大面积留白，弱化分隔线，用间距和层级而非线框来组织信息。
4. **丝滑流畅（Fluid）**：任何状态变化都有过渡，任何点击都有即时反馈，滚动稳定 120fps（ProMotion）不掉帧，绝不出现"白屏 → 内容突然弹出"。这是本项目的最高体验目标（见第 6 章）。
5. **克制（Restraint）**：一屏内不超过一个强调色焦点；玻璃与动效服务功能，不炫技；默认深色友好，也要在浅色下成立。

## 2. 平台与技术约束

| 项 | 约束 |
|---|---|
| 平台 | **macOS 26+（Tahoe 及以后）**，原生窗口应用。小众自用工具，**不向下兼容旧系统**，放心用最新 API |
| 设计语言 | **Liquid Glass（液态玻璃）** 为核心材质语言，直接用系统提供的 Liquid Glass API（`glassEffect` / 玻璃材质控件），不做手写模糊仿制 |
| 技术栈 | SwiftUI 为主（用 macOS 26 最新能力）+ 必要处 AppKit 桥接；AVFoundation 播放；零第三方 UI 库 |
| 窗口 | 支持自由缩放；最小窗口尺寸下布局不塌（见第 3.4 响应式）；记忆窗口尺寸/位置 |
| 外观 | 同时支持浅色 / 深色，跟随系统；深色为主打磨对象。玻璃材质在两种外观下都要成立 |
| 音源 | QQ 音乐 + 网易云，UI 层通过统一 `MusicProvider` 协议访问，**不感知具体平台**；仅在必要处用红/绿徽标区分来源 |
| 无障碍 | 支持 Dynamic Type（合理范围）、VoiceOver 标签、键盘全操作、`Reduce Motion` / `Reduce Transparency` 降级 |
| 系统集成 | 控制中心 / 媒体键 / Now Playing（已有，UI 需与之状态一致） |

## 3. 信息架构与导航

### 3.1 顶层结构

采用 macOS 标准**三栏 / 侧栏 + 内容区**布局：

```
┌────────────┬─────────────────────────────────────────┐
│            │  工具栏（返回/前进 · 标题 · 搜索 · 音源切换）│
│  侧栏       ├─────────────────────────────────────────┤
│ (Sidebar)  │                                         │
│            │            内容区 (Detail)               │
│            │        首页 / 搜索 / 详情页              │
│            │                                         │
├────────────┴─────────────────────────────────────────┤
│              底部播放条 (Now Playing Bar)              │
└───────────────────────────────────────────────────────┘
```

- **侧栏**：可折叠（`NavigationSplitView`），Liquid Glass 材质，透出下方内容。
- **底部播放条**：全局常驻，横跨整个窗口宽度，作为一层漂浮的 Liquid Glass 浮在内容之上。
- **全屏播放器 / 歌词**：从底部播放条唤起，以覆盖态（sheet / 全窗过渡）呈现，从播放条玻璃平滑"生长"展开。

### 3.2 侧栏分区

| 分组 | 条目 | 说明 |
|---|---|---|
| 导航 | 首页 | 推荐 / 排行 / 新碟聚合入口 |
| | 搜索 | 也可放工具栏搜索框，二选一或并存 |
| 资料库 (Library) | 喜欢的音乐 | 收藏的单曲 |
| | 最近播放 | 播放历史 |
| | （可扩展）我的歌单 | 预留 |
| 音源 (Sources) | 网易云音乐 / QQ音乐 | 切换当前浏览的音源；用色点/徽标标识 |

- 侧栏条目用 SF Symbols 图标 + 文案，选中态用系统强调色高亮。
- 音源切换：Apple Music 没有这个概念，是本 App 特有。设计上要让"当前在看哪个源"一目了然，但不喧宾夺主。

### 3.3 导航栈行为

- 内容区支持**前进 / 后退**（工具栏箭头 + 手势），像浏览器一样。
- 从任意列表点进详情页（歌单 / 专辑 / 歌手）压栈；标题栏显示当前层级。
- 详情页返回时保留上级滚动位置（不要回到顶部）。

### 3.4 响应式

- 侧栏可隐藏；隐藏后内容区接管全宽。
- 首页网格随窗口宽度自适应列数（如 2/3/4/5 列断点）。
- 窄窗时横向卡片排（排行榜）转为可横向滚动。
- 底部播放条在窄窗下允许折叠次要控件（音量、队列按钮收进溢出菜单）。

## 4. 界面清单（逐屏功能规格）

> 每屏给出：用途、内容、功能点、状态（加载 / 空 / 错误）。布局与视觉自由发挥。

### 4.1 首页 Home

**用途**：音乐发现入口，按当前音源展示。

**内容板块**（纵向滚动，每块含"标题 + 查看更多"）：
1. **推荐歌单**：封面网格，标题 + 播放量（`12.3万` 短格式）。
2. **排行榜**：横向卡片滚动（飙升 / 热歌 / 新歌 / 原创 等，见 `ChartCatalog`）。
3. **新碟上架**：专辑封面横滑或网格，含歌手名。

**功能点**：
- 卡片 hover 有微交互（轻微抬升 / 封面上浮出播放按钮）。
- 单击卡片 → 进入对应详情页。
- 悬停封面出现快捷"播放"按钮，点了直接开始播放该歌单/专辑，不必进详情。

**状态**：
- 加载：**骨架屏（skeleton）**占位，禁止白屏（见 6.4）。
- 空 / 错误：友好占位图 + 文案 + 重试按钮，绝不空白。

### 4.2 搜索 Search

**用途**：跨双平台搜索。

**内容**：
- 搜索框（工具栏或页内）。输入即联想（可选）；回车触发搜索。
- 结果按 **单曲 / 专辑 / 歌手 / 歌单** 四个 section（`SearchSection`）分类。
- **同时搜两个平台**，结果**按平台分组或用来源徽标标识**（设计时决定哪种更清爽）。

**功能点**：
- 分段控制（Segmented）在四类间切换，或分区并排展示。
- 单曲结果行支持双击播放 / 悬停显示播放键。
- 空查询态展示搜索历史或热门（可选，若 provider 无此能力则省略）。

**状态**：加载中转圈 / 无结果占位 / 网络错误重试。

### 4.3 详情页 Detail（三种）

统一采用**大头部 (Hero Header) + 曲目列表**结构。头部含大封面、标题、副信息、主操作按钮（播放 / 随机播放 / 收藏）。

**a) 歌单详情 PlaylistDetail**
- 头部：封面、歌单名、创建者、简介、播放量、曲目数。
- 主体：曲目列表（TrackList）。
- 操作：播放全部、随机播放、收藏歌单（若支持）。

**b) 专辑详情 AlbumDetail**
- 头部：封面、专辑名、歌手（可点进歌手页）、发行日期、曲目数、简介。
- 主体：曲目列表（可显示音轨序号）。

**c) 歌手详情 ArtistDetail**
- 头部：歌手头像、名字、简介。
- 主体：**热门单曲**（前若干首）+ **专辑网格**两段。
- 专辑点击进专辑详情。

**共性功能**：
- 头部可随滚动收缩 / 视差（可选，注意性能）。
- 曲目行悬停高亮 + 显示更多操作（收藏、加入队列、下一首播放）。

### 4.4 曲目列表组件 TrackList / TrackRow

**每行展示**：序号或封面缩略、标题、歌手、专辑（宽度够时）、时长（`mmss`）、来源徽标（跨源列表时）。

**行内功能**：
- **双击播放**该曲并设置上下文队列。
- 悬停显示：播放键、"喜欢"心形、更多菜单（加入队列 / 下一首 / 查看专辑 / 查看歌手）。
- 正在播放的行有明确的"播放中"指示（如动态音量条图标 + 高亮）。
- VIP / 付费曲目标记（QQ 匿名不可播时），播放时若跳过要有非阻塞提示。

### 4.5 底部播放条 Now Playing Bar（全局常驻）

**左区**：当前曲封面缩略 + 标题 + 歌手（点击封面 → 展开全屏播放器）。

**中区**：上一首 / 播放暂停 / 下一首；进度条（可拖拽 seek）+ 当前时间 / 总时长。

**右区**：随机、循环（关 / 全部 / 单曲三态）、音量、播放队列按钮、来源徽标（红=QQ / 绿=网易云）。

**功能点**：
- 进度条拖拽实时 seek，松手生效；hover 时加粗更易拖。
- 播放/暂停键状态与实际播放严格一致。
- 点击展开 → 全屏播放器；点击队列按钮 → 队列面板（inspector 或 popover）。

### 4.6 全屏播放器 Now Playing（沉浸态）

**用途**：沉浸式播放 + 歌词。

**内容**：
- **动态渐变背景**：取封面主色生成柔和渐变（Apple Music 风），随歌曲切换平滑过渡。
- 大封面（居中 / 偏左）。
- 曲目信息、可拖进度条、完整传输控件、音量。
- **同步滚动歌词**：当前行高亮居中，支持翻译副行；**点击某行歌词跳转**到对应时间。
- 关闭 / 最小化回到底部条。

**功能点**：
- 有歌词 / 无歌词两种布局（无歌词时封面更大 / 可视化）。
- 歌词滚动跟随播放平滑推进（缓动，非跳变）。
- `Reduce Motion` 下背景改为静态渐变、滚动改为直切。

### 4.7 播放队列 Play Queue

**用途**：查看 / 管理"接下来播放"。

**内容**：当前曲高亮 + 后续队列列表。

**功能点**：
- 拖拽重排；滑动 / 悬停删除单曲。
- 点击队列内某曲直接跳播。
- 显示随机 / 循环状态。

**呈现**：右侧 inspector 抽屉或 popover（自定，保证不遮挡核心操作）。

### 4.8 资料库 Library

- **喜欢的音乐**：收藏单曲列表（TrackList 复用），支持取消收藏。
- **最近播放**：按时间倒序的播放历史。
- 均为本地 JSON 持久化，UI 只读展示 + 基本操作。

### 4.9 登录 / 音质（QQ 音乐，次要流程）

- 菜单栏"登录 QQ 音乐"（⌘L）：**扫码登录**（面板内二维码 + 状态：待扫 / 已扫 / 确认 / 过期）或**粘贴 Cookie**。
- 音质切换：标准 128k / 高品质 320k。
- 登录态 / VIP 能力变化要在 UI 有轻量反馈；凭证过期时提示重新登录。
- 这是设置类流程，做成标准 sheet 即可，视觉从简。

## 5. 功能对齐清单（硬约束 · 必须全覆盖）

以下为 provider 已支持、UI 必须承接的能力。设计可改变呈现方式，但不可丢功能：

- [ ] 双音源（QQ / 网易云）浏览与切换
- [ ] 首页：推荐歌单 / 排行榜 / 新碟（按源）
- [ ] 搜索：单曲 / 专辑 / 歌手 / 歌单，双平台聚合
- [ ] 详情页：歌单 / 专辑 / 歌手
- [ ] 播放：队列、随机、循环（全部 / 单曲）、自动连播、双击播放
- [ ] 底部迷你播放条（含来源徽标）
- [ ] 全屏播放器：渐变背景 + 大封面 + 可拖进度 + 音量
- [ ] 同步滚动歌词（翻译副行 + 点击跳转）
- [ ] 播放队列管理（重排 / 删除 / 跳播）
- [ ] 资料库：喜欢的音乐 + 最近播放（本地持久化）
- [ ] 系统集成：控制中心 / 媒体键 / Now Playing 信息中心
- [ ] QQ 登录（扫码 / Cookie）+ 音质切换
- [ ] VIP / 付费曲目的可播状态提示与自动跳过

## 6. 交互与动效（"丝滑"的具体定义 · 本项目重点）

这一章是本次重做的**核心诉求**。"丝滑"不是玄学，拆成可验收的规则：

### 6.1 即时反馈
- 任何可点击元素都有 hover / pressed 态，按下即有视觉响应（≤100ms）。
- 播放/暂停、收藏、切歌等操作**乐观更新**：先改 UI，再等后台确认，失败才回滚 + 提示。

### 6.2 过渡而非跳变
- 视图切换（列表 → 详情、底部条 → 全屏）用**连续过渡**（淡入淡出 / 位移 / 共享元素），不硬切。
- 封面切换、渐变背景切换用交叉淡入。
- 进度条、歌词、音量都是**连续插值**推进，不逐帧跳。

### 6.3 弹性与自然曲线
- 优先用 SwiftUI `spring` 动画表达开合、抽屉、卡片抬升，参数偏"轻快不拖沓"。
- 避免线性缓动；用 ease-out / spring 让运动有物理感。
- **玻璃形变要连续**：Liquid Glass 元素在出现/消失/展开时应"流动"变形（拉伸、合并、分裂），而非硬切透明度。用系统玻璃容器承接这类形变过渡（如播放条 → 全屏播放器）。

### 6.4 加载体验（关键）
- **禁止白屏**。首屏与详情页加载用**骨架屏**占位，结构先出、内容后填。
- 图片渐进加载 + 占位底色（取封面平均色或中性灰），加载完成淡入。
- 已有内存 + 磁盘图片缓存，滚动回看不应重新闪烁。

### 6.5 滚动性能
- 长列表用懒加载（`LazyVStack` / `List`），目标 60fps（ProMotion 上 120fps）。
- 封面异步解码 + 缓存，滚动时不阻塞主线程。
- 大图降采样到显示尺寸，避免过度绘制。

### 6.6 手势
- 触控板：两指前进/后退导航、滚动惯性跟随。
- 进度条 / 音量支持点击定位 + 拖拽微调。
- 队列支持拖拽重排。

### 6.7 声音与状态一致性
- 所有"正在播放"指示（底部条、列表行、全屏、系统 Now Playing）**严格同步**同一状态源。
- 切歌 / 缓冲 / 暂停的状态转换都要有对应视觉，不留"不知道在干嘛"的空档。

### 6.8 无障碍降级
- 尊重 `Reduce Motion`：视差、渐变动画、滚动动画降级为直切 / 静态。
- 尊重 `Reduce Transparency`：材质退化为不透明背景。

## 7. 视觉语言（原则 + Token 约束，非像素稿）

### 7.1 颜色
- 以**系统语义色**为基（`NSColor` / SwiftUI `Color` 语义色），自动适配深浅色与对比度。
- 强调色（accent）：可跟随系统强调色，或定一个统一品牌色；一屏只有一个强调焦点。
- 来源徽标：QQ=红系、网易云=绿系（沿用现状），仅作小面积标识，不做大色块。
- 深色模式为主打磨对象，浅色也必须成立且对比达标（WCAG AA）。

### 7.2 液态玻璃（Liquid Glass）— 核心材质
- **Chrome 层全部用 Liquid Glass**：侧栏、工具栏、底部播放条、悬浮控件、popover、队列抽屉、全屏播放器的传输控件区，统一用 macOS 26 系统 Liquid Glass 材质（`glassEffect` / 系统玻璃控件），让框架层"漂浮"在内容之上，随下方内容折射、流动。
- **内容层不上玻璃**：专辑封面、列表内容、歌词是实体内容，直接呈现，不裹玻璃——玻璃只属于 Chrome，避免"处处玻璃"糊成一片。
- **一屏一到两层玻璃**为上限：玻璃是稀缺资源，堆叠多层会失去通透感和性能。播放条与侧栏可各一层，弹出层再叠一层，仅此而已。
- **玻璃控件成组**：同一功能区的玻璃元素用系统的玻璃容器（如 `GlassEffectContainer`）归组，让它们共享折射、在动效中合并/分裂，而不是各自为政。
- **深浅色都要成立**：玻璃在深色壁纸、浅色壁纸、纯色背景下都要清晰可读；文字落在玻璃上必须保证对比度（必要时叠系统的自适应前景色）。
- 用**间距和分组**建立层级，弱化实线分隔（必要处用极浅 hairline）。
- 圆角、阴影统一到一套 token；玻璃元素用系统推荐的**连续圆角（capsule / concentric）**，避免直角切玻璃。阴影克制、柔和。

### 7.3 字体
- 系统字体 SF Pro；用 macOS 标准文字层级（largeTitle / title / headline / body / caption）。
- 数字（时长 / 播放量）可用等宽数字避免跳动。
- 支持合理范围的 Dynamic Type。

### 7.4 图标
- 统一 SF Symbols，粗细 / 尺寸成套；播放控件用系统标准符号（play.fill / pause.fill / forward.fill 等）。

### 7.5 间距与栅格
- 定一套 4/8pt 基准间距 token，全局复用。
- 首页网格用响应式列数；卡片尺寸随断点缩放但比例一致。

### 7.6 设计 Token 建议（交给实现时落成常量）
建议维护一个轻量 Design System（现有已有 `DesignSystem/` 目录）：
- `Spacing`（4/8/12/16/24/32…）
- `Radius`（卡片 / 缩略图 / 按钮 / 玻璃连续圆角）
- `Glass`（玻璃层级与变体：常规 / 更清透 / 交互态；用哪些区域上玻璃的约定）
- `Elevation`（阴影层级）
- `Motion`（各类动画时长与 spring 参数常量 + 玻璃形变过渡，集中管理便于统一调）
- 颜色语义映射（背景 / 前景 / 次级文本 / 强调 / 分隔 / 玻璃上前景色）
